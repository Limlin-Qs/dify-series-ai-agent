# 一线声音提报智能体 — 数据准备指南

> 任务本质：口语化语音文本 → 意图分类（咨询/建议/投诉）→ 提取线路/工程层级 → 输出标准 JSON 表单。
> 知识库的作用：①工程层级树（把"凤朝区间"映射成 nodeIds 链）②历史数据（类别/标签的匹配样例）。

---

## 一、数据摸底（已实测核对）

| 文件 | 结构 | 内容 |
|---|---|---|
| 1 智慧工地工程层级.xlsx | Sheet `Result 1`：**9,240 行 × 6 列** | id / parentId / name / nodeType / nodeCode / isTerritoriality，是一棵**树**：项目(如6号线二期 id=1562) → 参建单位类型 → 标段 → 工区 → 站点/区间 |
| 5 一线声音历史数据.xlsx | 667 行 × 6 列 | 声音描述 / 声音类别(咨询/建议/投诉) / 声音标签(可多个，如"环境污染类;其他;生活保障类") / 所属线路(完整层级路径) / 声音来源 / 提报人身份 |

测试用例的期望输出（已给标准答案）：
```json
{"type": "2", "nodeIds": [1562, 1563, 3912, 2968, 3004, 3052],
 "nodeNames": "6号线二期/施工单位/土建施工/全线标/07工区/凤朝区间",
 "problemDescription": "凤朝区间卫生间马桶坏了，希望及时处理。",
 "checkLabelList": [15], "checkLabelNames": "其他-其他"}
```
→ 智能体必须把口语里的"凤朝区间"沿树回溯出**完整 id 链**（从根到叶 6 级），还要输出**标签的数字 ID**（如 15）。

## 二、⚠️ 练习包缺文件（重要）

考试说明列了 5 份资料，练习包只有 2 个 xlsx，**缺 3 个 txt**：
- `2 一线声音类别.txt`（类别枚举，如 咨询=1/建议=2/投诉=3 之类的 ID 映射——测试输出 type:"2" 需要它）
- `3 一线声音标签.txt`（标签 ID 映射——checkLabelList:[15] 需要它）
- `4 输出格式.txt`（JSON 输出模板）

**考场上**：先核对素材是否齐 5 份；缺了就找监考要。若实在没有，从历史数据反推枚举（类别只有3类，标签可从667行里去重收集），但 ID 数字无从得知——这是必须补齐的文件。

## 三、处理步骤（约15分钟）

1. **工程层级树 → 展开成"全路径表"**（关键一步）：
   - 原始是 id/parentId 邻接表，模型没法直接用；
   - 沿 parentId 逐层回溯，把**每个叶子/节点**展开成一行：`完整路径名 | 路径id链 | 末端节点id | 末端节点名`，如：
     `6号线二期/施工单位/土建施工/全线标/07工区/凤朝区间 | [1562,1563,3912,2968,3004,3052] | 3052 | 凤朝区间`
   - 入库后用户说"凤朝区间"就能直接召回整条 id 链，模型照抄即可，不用现场推理树结构。
2. **类别/标签/输出格式 3 个 txt 原样入库**（单独一个小库或打"枚举"标签），它们是给提示词引用的映射表，不要和历史数据混切。
3. **历史数据 667 行**：一行一块，保留 `描述→类别+标签+线路路径` 的对应关系，作为 few-shot 样例库。口语化、有错别字的原文**不要改正**——它正是"文化水平参差不齐"场景的训练样例。
4. 分类建库（考试说明要求"根据内容类型分类建立知识库，通过标签快速检索"）：建议 3 个库或 3 类标签——`层级树` / `枚举映射` / `历史样例`。

## 四、入库后召回验证

| 验证问题 | 应召回 |
|---|---|
| 凤朝区间 | 完整路径 + id链 [1562,...,3052] |
| 9号线一期01工区 | 路径 + id链 [1640,1642,4084,3969,2328]（测试用例2标准答案） |
| "马桶坏了"类历史声音 | 类别=建议/投诉、标签=生活保障类的样例 |
| 标签"其他"的ID | 15（来自 一线声音标签.txt） |

两个测试用例已带标准答案，直接当验收标尺：意图、nodeIds、checkLabelList 三项全对才算过。
