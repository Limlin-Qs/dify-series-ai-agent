## 核心模型：枢纽锚点

多网融合不直接合并六张表，而是以**枢纽（Hub）**为锚点组织数据：

```
国铁到发 ──┐
航空到发 ──┤                    ┌── 公交（末端接驳）
          ├── 枢纽 ── 地铁 ────┤
时刻表层 ──┘                    ├── P+R 停车场（截流接驳）
                                └── 共享单车（最后一公里）
```

- **干线层**（国铁、航空）：产生枢纽的到发客流需求，时刻表提供时间结构，专报提供量级。
- **骨干层**（地铁）：承担枢纽集散，是融合分析的主角。
- **末端层**（公交、P+R、共享单车）：补充地铁服务盲区和最后一公里。

每次分析先明确锚点枢纽（如 青岛站 / 青岛北站 / 胶东机场），再决定需要哪几层数据。
枢纽与地铁线路的对应关系、首末班时间查 [hub_registry.md](hub_registry.md)。

## 指标体系与公式

| 指标 | 公式 | 用途 |
|---|---|---|
| 地铁接驳分担率 | 枢纽地铁站进出站合计 / 枢纽吞吐合计 | 衡量地铁在枢纽集散中的份额 |
| 首末班覆盖率 | 1 − 未覆盖到发次数 / 到发总次数 | 地铁服务时间窗对早晚航班/列车的覆盖 |
| 高峰叠加 | 国铁到发高峰小时 ∩ 航班高峰小时 | 判断多方式客流峰值是否叠加于同一时段 |
| 方式结构演变 | 各方式占比的逐日均值/趋势 | 监测出行结构迁移（如出租车→网约车） |
| 末端接驳缺口 | 未覆盖人次 × 预估转向系数 | 估算溢出到公交/出租/P+R 的客流规模 |
| P+R 截流率 | P+R 停车场日均周转车次 / 枢纽机动车到达量 | 评估截流效果（需补充机动车数据） |
| 单车潮汐强度 | 枢纽片区早高峰还车数 / 晚高峰借车数 | 判断接驳方向性与调度需求 |

口径注意：

- 机场专报的"地铁分担合计"应与 `地铁合计人次 / 机场吞吐合计` 复算值一致；偏离 >2% 的天数超 10% 时按口径问题告警（fusion_analysis.py 已内置）。
- 方式占比中"其他"为配平项，可能出现负值，告警但不拦截。
- 国铁时刻表为季度运行图，无日期维度：与国铁相关的融合只做**时段结构**分析（小时分布、首末班覆盖），不做日级 join。

## 时空对齐规则

1. **时间粒度**：以小时为最细公共粒度。时段字段统一为 `HH-HH`（如 `07-08`）。
2. **跨日处理**：00:00–05:00 的到达计入前一自然日的接驳需求（夜间进港航班即此类）。
3. **空间映射**：方式站点 → 枢纽 的映射以 hub_registry.md 为准；新枢纽先登记再分析。
4. **单位统一**：客流一律"人次"，架次/列数保留原单位，占比一律 0~1 小数。

## 极视角节点分工

- **代码节点**：本 skill 的四个脚本（解析、校验、融合计算）。确定性指标、排序、聚合全部在代码节点完成。
- **模型节点**：只接收 fusion_analysis 输出的指标字典（JSON 摘要），负责解读原因、形成建议与报告正文；**不得重算指标、不得补造事实**。
- **32k 控制**：传入模型的只是指标摘要（通常 <2k tokens），禁止把标准化明细长表整体传入。
- 输入样例与报告字段的映射以中文 key 数据契约为准，字段新增必须先改 data_schemas.json 再改解析器。
