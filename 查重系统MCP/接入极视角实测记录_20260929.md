## 平台特性实测（写进客流MCP规范的坑）

1. **参数留空 = 显式传null**（不省略）。MCP服务端所有参数必须按"可能收到None"设计：
   - `_opt_str(v)`：非str归一空串
   - `_opt_int(v, default)`：非int归一默认值
2. **平台走标准SSE客户端**：GET /sse 建连 + POST /messages 通信。服务端必须 `transport="sse"`（http模式的/mcp端点平台连不上，400/404）
3. **工具定义更新后平台有schema缓存**：改了服务端必须重连/重连保存才生效
4. 画布参数可以用静态值直接填，不必开始节点定义变量（调试期最快路径）

## 本次踩坑清单（全流程）

| 现象 | 根因 | 解法 |
|---|---|---|
| 重启服务失败 | 8902被旧进程占用 | Get-NetTCPConnection -LocalPort 8902 查残留 + Stop-Process -Force |
| 平台GET /mcp 400 | http模式的/mcp只收POST | 换transport="sse"，端点/sse |
| GET /sse 404 | 还在跑http模式 | 同上，改完重启 |
| pydantic validation error: NoneType | 平台空参数传null | _opt_str/_opt_int归一（所有工具所有可选参数） |
| 防火墙加规则需提权 | netsh要管理员 | Start-Process -Verb RunAs |
