# 客流数据MCP服务 设计文档 V0.1

> 定位：为极视角智能体（客流分析/沿线活动应对/节假日等）提供**只读**的客流/预测/指标查询MCP薄壳
> 原则：MCP只做转发+校验+结果裁剪，不做业务计算——计算留在极视角代码节点，判断留给模型节点
> 日期：2026-09-28

## 一、边界（先定死）

1. **只读**：不给智能体任何写库/改配置的刀子。运营数据是正式口径，写入走人工或既有系统流程。
2. **薄壳**：每个工具=一个系统查询，内部就是HTTP转发，不复制业务逻辑。
3. **裁剪**：底层接口可能返回全量，MCP按需裁剪字段，保证返回体≤8k tokens，防撑爆模型32k上下文。
4. **连接**：MCP挂在能同时访问客流分析/客流预测/指标统计三个系统的服务器上（或各自网关可达），极视角通过McpToolCall节点调用。

## 三、暴露给极视角的返回契约

统一响应（全英文key，与运输计划配置维护项目一致）：

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": [ ... ],
  "count": 3
}
```

- 工具描述和入参schema用中文写清楚（模型读的），返回字段用系统原生中文字段名（客流系统页面口径本身就是中文，不翻译，减少一层映射错误）。
- 空值与0区分：预测系统明确要求空预测不返回0（字典里已有此坑记录）。
- date缺省=昨日/今日（按各工具语义），格式YYYY-MM-DD。
- 单位字段随数据返回（万人次/人次/%），不折算。

## 三点诚实的边界提醒（写给评审）

1. **接口地址未定**：本字典是“页面展示口径”，三个系统底层的HTTP API路径/鉴权方式没有拿到。MCP代码里HTTP调用层留抽象接口，地址/鉴权配置化，拿到真实API后填入即可，不改工具逻辑。
2. **满载率超100%问题**：3号线青岛北站—永平路568.92%这类数据，口径未核验前MCP原样透传+附warning字段，不做修正。
3. **同页面多系统边界**：客流分析/客流预测/指标统计是三个页面模块，底层是否同网关同鉴权未确认——若各自独立，MCP配置文件按系统分三段管理。
