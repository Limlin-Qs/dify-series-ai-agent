# 2025年运作命令模板要素提炼

> 数据来源：33份《2025年N号运作命令》全文（语料2025_text/，PDF文本层提取，逐字统计）。
> 用途：运作命令生成智能体 v1 模型节点提示词的生成模板依据。

## 1. 文档双层结构

每份发布物 = 红头通知（主件） + 命令正文（附件1） + 运行图（附件2，rar包或PDF）。

### 1.1 通知层（红头文件）要素

| 要素 | 规律 | 统计确认 |
|---|---|---|
| 版头 | 青岛地铁运营有限公司文件 | 33/33 |
| 发文字号 | 青地铁运发〔2025〕N号 | 33/33 |
| 主送 | "线网管控中心、各运营中心："（1-19号）/ "各中心："（20号起） | 33/33 |
| 正文 | 一段式：调图缘由（为…）+ 起始日期 + 调整对象/幅度 + "现编制《2025年N号运作命令》及相关运行图，请做好相关准备工作。" | 33/33 |
| 附件清单 | 附件：1.2025年N号运作命令 2.列车运行图（或具体图名如《T02031运行图》） | 33/33 |
| 落款 | 青岛地铁运营有限公司 + 成文日期（生效日的前1-3天） | 33/33 |
| 抄送 | 市交通运输局、市公安局地铁分局、公司领导、相关部室 | — |

**关键结论：发文字号N是公司全年发文流水号，与命令号无函数关系**（1号命令=文号4，33号命令=文号338）。生成时文号必须留占位符，不得编造。

### 1.2 命令层（附件1）要素

标题：`2025年N号运作命令`（"2025 年 N 号"字间有空格，PDF提取特征）。

## 2. 命令正文章节结构（两种变体）

- 变体A（28/33份）：一、运作时间段 → 二、ATS系统中留存运行图 → 三、调图风险 → 四、注意事项
- 变体B（5/33份：5、14、19、20、21等）：一、运作时间段 → 二、ATS系统中留存运行图 → 三、注意事项
- 判定规则：**调图风险章节仅在有实质性风险项点时出现**（微调/换图类命令有，常规延续类无）。v1按"用户提供风险项点则生成该章，否则省略"处理。

## 3. 各章节模板

### 3.1 一、运作时间段（33/33）

首句固定句式（33/33完全一致）：
```
{YYYY}年{M}月{D}日起至另有通知时止执行的列车运行图如下：
```

正文为表格，列头固定：`线别 | 运作时间段 | 执行运行图 | 运营时间 | 备用车安排`

行要素：
- 线别：1/2/3/4/6/8号线、蓝谷快线、西海岸快线（8条线，固定顺序）
- 运作时间段：生效日期 + 时段条件（逢工作日/逢周末/全天/特定日期段如"2月13日-15日"）
- 执行运行图：《Z/T/Y五位编号》
- 运营时间：HH:MM-HH:MM（跨年节假日可到"次日02:58"，见33号）
- 备用车安排：图定备车 / 注意事项N（引用注意事项条目号）/ -
- 表尾注（可选）："注：表格中加粗运行图为本次新编运行图。"或"…本次调整运行图，前期已下发。"

### 3.2 二、ATS系统中留存运行图（33/33）

首段固定句式（仅一处部门名差异）：
```
{起始日期}起至另有通知时止，各线路ATS系统中仅留存下列运行图。
其他运行图由{各运营中心|自动化中心}移出ATS系统并做好备份。
```
（20份"各运营中心"，10份"自动化中心"——2025年5月架构调整后现行口径=**自动化中心**，已确认（2026-10-10，组织架构佐证），v1.1提示词按"自动化中心"。）

正文为多页大表：`线别(8列) | 备注`。备注类别（按频率）：常规(工作日/周末)、延时(工作日/周末)、低运量、冰雪储备、汛期工作日、汛期周末、节假日、其他。表内为全量运行图编号（每期约100-150个Z/T编号）。

**v1策略：此表数据量最大且为全量留存清单，不适合模型生成——按"上期清单+本期变更"做代码节点合并，模型只描述变更。**

### 3.3 三、调图风险（28/33，条件章节）

首段半固定句式（首尾固定，中段为本次调图项点描述）：
```
本次（主要）调图项点{为/一是…二是…三是…}：{调图项点描述}。
调图风险项点梳理如下，请相关专业提前做好预想和处置。
```
调图项点类型语料库（2025年实际出现过）：列车牵引节能测试、ATO节能曲线测试、节假日运输安排（春节/五一/端午/国庆中秋）、演唱会/音乐节/啤酒节/马拉松增运力、计划性延时运营、限速纳入运行图、小交路调整、折返股道更换、旅游旺季运力回调、春运调休。

正文为表格：`线路 | 乘客服务 | 行车组织 | 生产运作`（无风险项用"-"）。

## 4. 编号与引用体系

- 运行图编号：Z/T/Y + 5位数字（Z=常规图，T=节假日/特殊图，Y=备用）。示例：Z01140(1号线工作日)、T01033(1号线节假日)。
- 线路代号（编号前2位）：01=1号线, 02=2号线, 03=3号线, 04=4号线, 06=6号线, 08=8号线, 11=蓝谷快线, 13=西海岸快线。
- 车次号：6位数字（如061006次）。
- 命令号：年度内顺序编号；生效日期间隔约1-4周（2025年33期，平均11天/期）。

## 5. v1生成策略裁定（喂给workflow模型节点）

1. **固定骨架代码化**：章节标题、首句句式、表格列头、固定套话14条 → 模板库（不进模型prompt原文，作为few-shot+模板填充）。
2. **模型职责收窄**：模型只做三件事——(a)从用户输入提取结构化要素（调图缘由/日期/线路/图号变更/风险项点）；(b)生成调图项点描述段（半固定句式）；(c)生成每期新写注意事项条目（每期0-5条，参考历史同类条目风格）。
3. **ATS留存表**：代码节点做"上期全量+本期增删"合并，模型不碰。
4. **文号**：占位符〔2025〕___号，人工补。
5. **检索维度**：按"调图缘由类型"（节能测试/节假日/演唱会/限速/延时…）检索同类历史命令作为few-shot，命中类型后新写条目风格一致性最高。
6. **双变体路由**：输入含风险项点→变体A（四章），否则变体B（三章）。
